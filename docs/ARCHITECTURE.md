# معماری NikType

## نمای کلی

NikType با رویکرد Clean Architecture و سه ماژول Gradle ساخته شده است. دو ماژول موتور **Kotlin خالص** هستند (بدون هیچ وابستگی اندرویدی) تا تست‌پذیر، سریع و قابل حمل باشند؛ ماژول app فقط لایه نمایش و اتصال به سیستم اندروید است.

```
┌──────────────────────────────────────────────────────────┐
│                     app (Android)                        │
│  ┌────────────┐  ┌─────────────┐  ┌───────────────────┐  │
│  │ IME Service│→ │ Keyboard     │→ │ Settings / Themes │  │
│  │ (System)   │  │ Controller   │  │ Onboarding / Voice│  │
│  └────────────┘  └──────┬───────┘  └───────────────────┘  │
│                         │ ports                           │
├─────────────────────────┼─────────────────────────────────┤
│  keyboard-engine        │  prediction-engine              │
│  (Kotlin خالص)          │  (Kotlin خالص)                  │
│  • geometry/chیدمان‌ها   │  • dictionary (Trie)            │
│  • touch/احتمالات لمس   │  • correct/اصلاح خودکار         │
│  • کالیبراسیون          │  • suggest/prediction           │
│                         │  • context/بی‌گرام و کاربر       │
│                         │  • swipe/رمزگشای ژست            │
└─────────────────────────┴─────────────────────────────────┘
```

## مسئولیت ماژول‌ها

| بخش | مسئولیت | وابستگی |
|---|---|---|
| `keyboard-engine` | هندسه چیدمان، سازنده لایه‌های فارسی/انگلیسی، موتور تشخیص لمس، پروفایل‌های انگشت، کالیبراسیون | — |
| `prediction-engine` | دیکشنری Trie، اصلاح خودکار، پیشنهاد/پیش‌بینی، بی‌گرام، مدل کاربر، سوایپ، ایموجی، ابزار متن فارسی | keyboard-engine (فقط enumها و TouchPoint) |
| `app` | سرویس IME، رندر و ورودی، تنظیمات، تم‌ها، onboarding، صوت، ذخیره‌سازی | هر دو موتور |

نقشه با ساختار درخواستی پروژه:
`keyboard/` و `keyboard-engine/` → ماژول keyboard-engine · `prediction-engine/` و `language-engine/` → ماژول prediction-engine · `touch-engine/` → بسته `engine.touch` · `settings/` و `themes/` و `onboarding/` و `personalization/` → بسته‌های app · `data/` → بسته `app.data` + پورت `LearningStore` · `domain/` → خود دو ماژول خالص (لایه دامنه واقعی) · `tests/` → `src/test` ماژول‌های موتور.

## جریان یک لمس (Data Flow)

```
لمس کاربر

   ▼

   │                                              │
   │                                    ┌─────────▼──────────┐
   │                                    │ TouchResolver      │

   │                                    │ + کالیبراسیون      │

   ▼                                              ▼

```

## الگوریتم تشخیص لمس (touch/TouchResolver)

برای هر کلید k با مرکز c_k و لمس t در نقطه (x, y):

1. **احتمال پایه (گاوسی):**
   `P(k) = exp( −½ [ ((x−c_x)/σx)² + ((y−c_y)/σy)² ] )`
   σx، σy نسبت به میانگین ابعاد کلیدها مقیاس می‌شوند — پس الگوریتم با هر اندازه کیبورد کار می‌کند.

2. **شکل کلید:** اگر لمس داخل مستطیل کلید باشد با `insideBonus` تقویت می‌شود.

3. **کلیدهای مجاور:** اگر لمس تا ۱۰ پیکسل از مرز مشترک کلید مجاور باشد، احتمال آن کلید با ضریب `1 + neighborWeight × (1 − d/10)` تقویت می‌شود. در پروفایل Large Fingers مقدار neighborWeight از 0.30 به 0.55 افزایش می‌یابد — یعنی در لمس‌های مبهمِ مرزی، مجاورها به‌درستی و با وزن بیشتر در نظر گرفته می‌شوند.

4. **تطبیق سرعت:** σ با سرعت تایپ تا ضریب `speedAdaptMax` بالا می‌رود؛ در تایپ سریع لمس‌های شتاب‌زده درست تفسیر می‌شوند.

5. **کالیبراسیون کاربر:** انحراف لمس از مرکز کلید با میانگین متحرک (EMA=0.06) یاد گرفته و در لمس‌های بعدی جبران می‌شود (سقف ۳۰٪ ابعاد کلید).

6. خروجی نرمال‌شده به لایه پیش‌بینی می‌رود تا در سطح واژه رفع ابهام شود.

## اصلاح خودکار بدون «انتخاب اشتباه»

قواعد سخت‌گیرانه (correct/AutoCorrector):
- واژه‌ی درست (موجود در دیکشنری یا واژه‌نامه کاربر) **هرگز** تغییر نمی‌کند.
- واژه‌های کوتاه‌تر از ۳ نویسه، حاوی رقم، آدرس یا شبیه نام خاص اصلاح نمی‌شوند.
- فاصله لونشتاین حداکثر ۲ — و فاصله ۲ فقط برای واژه‌های بسیار پرتکرار (≥1200).
- جایگزینی نویسه‌ای که از کاندیدهای لمسی همان موقعیت نیامده، فقط با فاصله ۱ پذیرفته می‌شود.
- بازگردانی: با نخستین Backspace واژه اصلی برمی‌گردد.

## رمزگشای سوایپ (swipe/SwipeDecoder)

مسیر به ~۱۴ نقطه نمونه‌برداری می‌شود؛ نامزدها از میان واژه‌هایی که با کلید شروع و پایان مسیر هم‌خوانی دارند انتخاب و با «فاصله متوسط نقاط تا مراکز حروف واژه (هم‌ترازی تناسبی) − پاداش بسامد» رتبه می‌شوند.

## کارایی

- رندر کیبورد در **یک Canvas** انجام می‌شود — بدون گره ترکیب به‌ازای هر کلید؛ فقط حالت‌های تغییر (کلید فشرده، پاپ‌آپ) بازترسیم می‌شوند.
- همه پردازش‌های سنگین (جستجوی واژه، رمزگشای سوایپ، ذخیره‌سازی یادگیری) روی Dispatchers.Default/IO با مهار jobهای کهنه.
- مدیریت چندلمسی دستی با یک حلقه pointerInput و ماشین حالت per-pointer — بدون تاخیر در ثبت لمس‌های متوالی.
- دیکشنری‌ها یک‌بار در عمر پروسه ساخته می‌شوند؛ ظرفیت یادگیری با حذف LRU/کم‌شمارش محدود می‌شود.
- تایپ پایه به اینترنت وابسته نیست (برنامه اصلاً مجوز INTERNET ندارد).

## چرخه عمر سرویس

`NikTypeImeService` یک `ServiceLifecycleOwner` می‌سازد و به `ComposeKeyboardHost` وصل می‌کند تا Compose داخل IME با Lifecycle درست کار کند. در `onDestroy` همه jobها لغو و مدل یادگیری flush می‌شود. در فیلدهای رمز (`inputType`) پیشنهادها خاموش و یادگیری غیرفعال می‌شود.
